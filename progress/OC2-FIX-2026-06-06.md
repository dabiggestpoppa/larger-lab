## Root Cause (FINAL)

Two layered problems:

1. **Bad model registration.** Config had:
   ```json
   "agents": { "defaults": { "model": "inclusionai/ring-2.6-1t" } }
   ```
   OpenClaw 2026.5.7's resolver splits model IDs on `/` and treats the first segment as the **provider name**. So `inclusionai/ring-2.6-1t` → provider `inclusionai`. But only `openrouter` and `nvidia` were registered as providers. Result: every model call failed with `FailoverError: Unknown model: inclusionai/ring-2.6-1t`.

2. **Two config files, not one.** OpenClaw has TWO config locations that get confused:
   - `C:\Users\wifik\.openclaw-2\openclaw.json` — the "primary" config (what `openclaw config` CLI reads)
   - `C:\Users\wifik\.openclaw-2\.openclaw\openclaw.json` — the **actual** config the gateway reads (doubles `.openclaw`)
   
   Previous attempts edited the primary file. The gateway was reading the deeper file (which still had `inclusionai/ring-2.6-1t`). That's why all 14 previous attempts failed.

## What Fixed It

1. Stopped the gateway cleanly (`Stop-ScheduledTask OpenClaw-2-Gateway` + kill node process on PID holding port 18790)
2. Edited BOTH config files:
   - `agents.defaults.model` → `openrouter/owl-alpha`
   - `agents.defaults.subagent.model` → `openrouter/owl-alpha`
   - Removed `inclusionai/ring-2.6-1t` and `minimax/minimax-m3` from `agents.defaults.models`
   - Removed `inclusionai/ring-2.6-1t` and `minimax/minimax-m3` from `openrouter` provider's `models[]`
   - Removed `minimax` plugin entry (model no longer exists)
   - Updated `meta.lastTouchedVersion` and `wizard.lastRunVersion` from `2026.6.1` → `2026.5.7` (stop spurious version warnings)
3. Restarted via scheduled task → gateway booted cleanly, model resolution succeeded (9552ms), no `FailoverError`

## Why Previous Attempts Failed

| # | Attempt | Why It Failed |
|---|---------|---------------|
| 1-2 | Kill/restart, change model to `openrouter/auto` | Live-edit was overwritten by OpenClaw on startup; the deeper config was never touched |
| 3-4 | Clean reinstall, `openclaw doctor --fix` | Doctor runs against the wrong (primary) config; doesn't sync to the deeper one |
| 5-7 | Delete session, change profile, add `inclusionai` provider | OpenClaw 2026.5.7 rejects unknown providers during validation — the addition gets stripped |
| 8-9 | Change model to `owl-alpha` | Edited the WRONG file (the one CLI reads, not the one the gateway loads) |
| 10-14 | Disable cron, delete scheduled task, downgrade OpenClaw, etc. | None addressed the real config path mismatch |

## Key Lesson

**The two config files must be edited together** when working with `openclaw gateway run` outside of `openclaw config set`. The CLI's `set`/`patch` commands don't reach the deeper `.openclaw-2/.openclaw/openclaw.json` file that the gateway actually uses.
