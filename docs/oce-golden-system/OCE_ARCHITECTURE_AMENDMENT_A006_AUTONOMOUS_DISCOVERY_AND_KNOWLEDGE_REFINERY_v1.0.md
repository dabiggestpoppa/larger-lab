# OCE Golden System
## Amendment A-006 — Autonomous Discovery and Knowledge Refinery

**Document ID:** OCE-AMEND-A006  
**Version:** 1.0  
**Status:** PROPOSED FOR OPERATOR RATIFICATION  
**Parents:** OCE Constitution 1.1; A-005 proposed  
**Build authorization:** None

## 1. Decision

Larger Lab shall maintain a governed discovery and knowledge-refinery capability that continuously identifies external and internal resources capable of improving institutional knowledge, sensors, data, algorithms, infrastructure, validation, execution, or agent capability.

Discovery is not generic browsing. Search demand originates from unresolved institutional state and is prioritized by expected information value, novelty, dependency importance, cost, risk, and potential reuse.

## 2. Endogenous search demand

Search demand may be generated from canonical records including:

- EvidenceGap;
- CapabilityGraph gaps;
- sensor/data gaps;
- blocked research;
- repeated worker failures;
- unresolved contradictions;
- portfolio weaknesses;
- execution limitations;
- validation bottlenecks;
- provider drift;
- new market structure;
- security/dependency changes;
- operator-created research questions.

Every autonomous search task records why it exists and what evidence would satisfy it.

## 3. Scout classes

The platform shall support runtime-neutral scout roles including:

- capability and GitHub scout;
- release/dependency scout;
- academic/paper scout;
- dataset/provider scout;
- market-structure/microstructure scout;
- crypto source and protocol scout;
- execution infrastructure scout;
- internal archaeology scout;
- license/rights/security scout.

A scout has discovery authority only. It cannot silently install, merge, trade, promote strategy claims, expose secrets, or mutate production systems.

## 4. SourceRecord and SourceGraph

Every discovered object receives a versioned SourceRecord containing at minimum:

- source identity and canonical URL/location;
- source type;
- author/owner;
- version/commit/date;
- license/rights/retention constraints;
- integrity/hash when obtainable;
- claimed capabilities or findings;
- extracted evidence status;
- related existing institutional objects;
- novelty disposition;
- downstream consumers;
- recheck trigger.

SourceGraph links sources to claims, capability atoms, mechanism cards, datasets, experiments, Research Genome atoms, and negative knowledge.

## 5. Novelty disposition

A resource must be compared against current institutional capability before expensive investigation.

Canonical dispositions include:

- ALREADY_COVERED;
- STRONGER_IMPLEMENTATION_CANDIDATE;
- PARTIAL_CAPABILITY_UPGRADE;
- NEW_CAPABILITY_CANDIDATE;
- NEW_SENSOR_OR_DATA_SURFACE;
- NEW_MECHANISM_OR_RESEARCH_HYPOTHESIS;
- EXECUTION_OR_INFRASTRUCTURE_CANDIDATE;
- REUSABLE_AGENT_OR_CODING_CAPABILITY;
- DATA_OR_RIGHTS_BLOCKED;
- DUPLICATE_OR_REJECTED;
- HIGH_VALUE_STRATEGIC_CANDIDATE.

Novelty is relative to what Larger Lab already possesses, not to what is fashionable externally.

## 6. Knowledge Refinery

Raw sources shall be transformed into reusable institutional objects rather than indefinitely re-read as prose.

Possible outputs include:

- ClaimRecords;
- CapabilityAtoms;
- MechanismCards;
- DatasetCandidates;
- Strategy/Research Genome atoms;
- validation methods;
- execution archetypes;
- implementation patterns;
- negative knowledge;
- source-grounded questions.

The refinery preserves links back to exact source evidence.

## 7. Internal archaeology

Larger Lab must search itself using the same standards applied to external resources.

Candidates include superseded branches, legacy engines, old experiments, TB Forward research, MVE, CEREBUS implementations, capital-routing work, archived agent tools, failed prototypes, infrastructure patterns, and repair evidence.

Internal age or prior failure does not imply valuelessness. A failed system may contain a valuable test, mechanism, component, or anti-pattern.

No legacy performance claim bypasses current validation.

## 8. Corpus-scale strategy mining

Large external strategy repositories such as FMZ-style corpora are treated as research ore.

Agents shall not equate file count with independent hypotheses. The refinery should extract mechanism, observation, state/filter, entry, exit, invalidation, risk, sizing, execution, and validation atoms; detect clones and superficial parameter variants; and cluster related strategies into mechanism and execution families before expensive testing.

The goal is to transform thousands of strategy files into a smaller, queryable Research Genome.

## 9. Search feedback and compounding

Discovery quality must improve from institutional outcomes.

SearchPolicy may learn from:

- which resource classes produced promoted capabilities;
- which sources repeatedly produced duplicates/noise;
- which sensors closed important evidence gaps;
- which mechanism families repeatedly failed;
- experiment information gain;
- cost/time to validate;
- later operational value;
- unresolved high-VOI questions.

This learning changes priority, not authority. Search optimization cannot promote truth by itself.

## 10. Intake safety

External code and resources remain quarantined until applicable checks pass.

Depending on resource type, checks include:

- license/rights;
- source integrity;
- dependency and supply-chain risk;
- static inspection;
- credential behavior;
- network behavior;
- data exfiltration risk;
- sandbox execution;
- reproducibility;
- compatibility with canonical contracts.

Fork/adapt/reimplement/wrap/sidecar decisions are explicit and evidence-backed.

## 11. Domain adapters

B6 should own generic discovery/refinery surfaces. Domains add specialized adapters.

Quant adapters may produce HypothesisSpec, MechanismCard, DatasetCandidate, ResearchGenome, StrategyCandidate, or ExperimentCandidate.

Crypto adapters may produce sensor/source candidates, venue-mechanics candidates, capital-field source candidates, protocol/mechanism candidates, and evidence-gap closures.

Other future domains reuse the same generic discovery contract without inheriting Quant semantics.

## 12. Operator experience

The operator should receive high-value summaries rather than raw discovery volume.

Examples:

- five materially new capabilities found this week;
- three resources likely to close active evidence gaps;
- two important provider changes;
- one research paper contradicting a promoted mechanism;
- ten new repos ignored as duplicates;
- one candidate requiring operator approval for licensing or spend.

## 13. Acceptance tests

A-006 is accepted only if future implementation proves that:

1. at least one search task is generated from an internal evidence/capability gap;
2. a duplicate popular repo is rejected before expensive sandboxing;
3. an internal legacy artifact and an external repo pass through the same novelty/refinery pipeline;
4. a strategy corpus is clustered/de-duplicated before backtesting;
5. every promoted extracted object traces to exact source evidence;
6. search priorities change after measured institutional outcomes;
7. scout failure cannot mutate canonical truth or production systems.

## 14. Operator decision

Proposed decision: `RATIFY_A006_AUTONOMOUS_DISCOVERY_AND_REFINERY`.

Ratification authorizes planning only, not autonomous crawling, installs, purchases, or code integration.
