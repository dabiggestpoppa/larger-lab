## 0. Executive decision

There is **one OCE**.

The current repository contains two deliberately different development hemispheres:

1. **Operational hemisphere** — how OCE safely exists, persists, authorizes, executes, recovers, and verifies real effects.
2. **Epistemic hemisphere** — how OCE safely knows, reasons, learns, disagrees, discovers anomalies, metabolizes knowledge, and changes its own abstractions under governance.

These are not competing products. They are two development surfaces of the same future institution.

The end state is a **single durable institutional operating system with a deterministic operational substrate and a separately tested adaptive cognitive/epistemic layer**.

No branch, model, runtime, research lab, or domain project becomes a second source of constitutional truth.

The operational and institutional lines are heavily diverged and contain different classes of work. A raw merge would mix:

- newer production/runtime implementation;
- older snapshots of implementation files;
- proposed amendments;
- experimental institutional engines;
- stress harnesses;

After G10, create a dedicated convergence branch **from the then-current `oce-program-build` head**.

Suggested future branch:

- required runtime/service changes;
- independent stress-suite or productionized evaluator surfaces;
- integration tests and migration contracts.

Old experimental implementation copies are not automatically transplanted.

The convergence branch cannot claim success until it proves, at minimum:

- cold-start reconstruction from canonical records;
- transcript-independent handoff;
- worker/runtime replacement;
- authority separation;
- effect verification;

- no regression of the operational OCE safety/recovery surface.

Only then is integration into `main` eligible for operator review.
