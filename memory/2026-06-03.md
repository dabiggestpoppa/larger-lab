## EURUSD/USDCHF WR Discrepancy Investigation

### Finding
- Multi-asset run (5/31) showed EURUSD 85% WR, USDCHF 84.9% WR
- My per-asset backtest (6/2) showed EURUSD 44% WR, USDCHF 40% WR
- ONLY these 2 assets show the discrepancy — all other assets match between runs
- Trade count also differs: 1163 vs 886 (EURUSD), 1153 vs 847 (USDCHF)

### What I confirmed (no code changes, read-only investigation)
- Data files identical (same bars, same date range, same file sizes)
- Engine code (`symmetry_trap.py`) unchanged since 6/2 3:38 PM
- Both runs use same `SymmetryTrapBacktest` class
- SL placement is correct (above entry for SHORT, below for LONG)
- Using same code path gives same result — both produce 44%

### Theory timeline
1. 5/30 engine: `sl_price = impulse_extreme` (buggy — SHORT SL below entry = in profit direction, never hit)
2. 6/2 10:49 engine: `sl_price = OCC extreme` (no spread buffer)
3. 6/2 16:37 engine (current): `sl_price = OCC extreme + spread_buffer`

### Paradox
- If old engine had SHORT SL in profit direction, SHORT trades would NEVER hit SL → inflated WR
- But OLD engine's SL check for SHORT (`bar.close >= sl_price`) with sl_price below entry would actually trigger IMMEDIATELY (price already above impulse low)
- So old engine should give LOW WR for SHORT, not high 85%
- This means the multi-asset 85% WR was NOT from the old engine either — there's a third version or different code path
