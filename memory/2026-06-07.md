## Issues Found & Fixed

### 1. Duplicate Process Explosion (29+ Python processes → 10)
- **Root cause**: pm2_watchdog.py (PID 10828) was running alongside manual process spawning
- **Compounding factor**: `.venv\Scripts\python.exe` on this system is a uv shim that spawns `uv\python\cpython-3.12` as a child — making every venv-launched process appear as 2 PIDs
- **pm2_watchdog bug**: `check_process()` uses `tasklist` which can't distinguish venv-shim from uv-child, AND it was using the wrong START_CMD (venv python → uv shim → confusion cycle)
- **Fix**: Killed pm2_watchdog entirely. Restarted all processes with SYSTEM Python (`Python311\python.exe`) which doesn't create uv shim duplicates
- **Result**: Exactly 1 process per service, clean

### 2. MT5 Account Flipping (Live ↔ Demo, 7 disconnects)
- Observed MT5 terminal switching between Live (650898) and Demo (1114712) accounts 7 times
- One Demo authorization failed ("Invalid account")
- **Root cause**: Multiple bridge instances fighting over MT5 terminal connection
- **Fix**: Single bridge instance resolved this

### 3. Health Check System
- **Disabled**: pm2_watchdog.py (fundamentally broken for this uv-venv setup)
- **Created**: `scripts/health_check.py` — lightweight monitor that:
  - Uses PowerShell for reliable process enumeration
  - Auto-restarts dead processes with `--fix` flag
  - Checks MT5 terminal, OC2 gateway, OCE backend ports
  - Logs to `logs/health_check.log`
- **Cron jobs active**:
  1. Hourly health check (runs `--fix` auto-restart)
