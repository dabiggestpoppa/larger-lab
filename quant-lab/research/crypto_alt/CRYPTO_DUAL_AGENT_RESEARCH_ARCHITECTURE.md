# CRYPTO DUAL-AGENT RESEARCH ARCHITECTURE

**Branch:** `agent/crypto-quant-foundry`  
**Status:** Research workflow architecture  

## Purpose

Run two complementary research roles without allowing exploratory side paths to derail the main terrain program.

## Agent 1 — MAIN FIELD CARTOGRAPHER

Primary responsibility:

- build the canonical crypto terrain
- maintain PIT truth
- expand datasets and ontology
- map global/chain/sector/rank/wallet/venue structure
- identify robust mechanisms and structural states
- preserve nulls, contradictions, and observational limits
- keep the main roadmap coherent

Agent 1 does not chase every derivative hypothesis immediately.

Agent 1 emits structured findings that can become inputs to Agent 2.

## Agent 2 — DERIVATIVE / SIDE-LANE EXPLORER

Primary responsibility:

Take findings, nulls, anomalies, side hypotheses, and alternative interpretations produced by Agent 1 and test them deeply without mutating the main terrain narrative prematurely.

Examples:

- lower-field / bottom-rank behavior
- hidden-state reconstruction
- alternate horizon structure
- local response surfaces
- edge cases
- failed pathways
- conditional reversals
- regime-dependent direction flips
- candidate hidden Markov structure
- side hypotheses generated from new datasets

Agent 2 acts as a pressure-test and hypothesis laboratory.

## Self-Reinforcing Loop

1. Agent 1 maps terrain and creates canonical data/artifacts.
2. Agent 2 reads only committed Agent-1 outputs plus preregistered side hypotheses.
3. Agent 2 tests derivatives, anomalies and alternate explanations.
4. Agent 2 classifies findings as NEW_NODE / MERGE / DISSOLVE / NULL / DATA_BLOCKED.
5. Only findings that survive Agent-2 validation are proposed back to Agent 1.
6. Agent 1 decides whether they belong in the canonical field map.
7. The richer canonical map creates new derivative questions for Agent 2.

This is a research flywheel, not two agents independently optimizing strategies.

## Databank Separation

Maintain two logical databanks:

### Canonical Terrain Bank

Produced by Agent 1.

Contains:

- source truth
- PIT universes
- canonical features
- ontology
- main mechanism maps
- state definitions
- hierarchy maps
- validated structural findings

### Derivative Insight Bank

Produced by Agent 2.

Contains:

- side hypotheses
- anomaly studies
- alternate conditioning
- hidden-state candidates
- response surfaces
- failed and null derivative tests
- speculative interpretations clearly labeled as such

Nothing enters the Canonical Terrain Bank automatically.

## Hidden-State / HMM Rule

Agent 2 is authorized to investigate latent-state / HMM-like structure only when observable evidence justifies it.

Use hidden-state methods to answer:

- whether failures of an 80% pattern cluster into distinct observable/latent regimes
- whether directional relationships flip because the system occupies unobserved states
- whether recurrent transition sequences imply a small latent state space

Do not use HMMs merely because they are available.

Start with transparent state clustering / conditional analysis first.

If a hidden-state model is used:

- compare against simpler baselines
- use causal/closed-time features only
- report state stability
- report transition stability
- avoid naming states based on outcome hindsight
- preserve uncertainty in state assignment

## Shared Research Doctrine

Both agents obey:

**Observe -> Compress -> Perturb -> Reconstruct -> Localize -> Formalize.**

Both agents preserve:

- PIT truth
- no leakage
- nulls
- failed hypotheses
- multiple-testing accounting
- observational limits
- causal-evidence ladder

## Same-Branch Concurrency Safety

Both agents may contribute to the same program branch, but should not edit the same files concurrently.

Preferred operational pattern:

- Agent 1 owns `crypto_foundry/` canonical terrain paths.
- Agent 2 owns a dedicated derivative path such as `crypto_alt/derivatives/` or `crypto_foundry/derivatives/`.
- Each agent commits small checkpoints frequently.
- Before push, pull/rebase or fetch latest branch state.
- If branch head moved, reconcile cleanly before push.
- Never force-push over the other agent's work.

If concurrent push collisions become frequent, use temporary child branches and merge back into `agent/crypto-quant-foundry`.

## Promotion Rule

A derivative finding may be proposed for canonical promotion only if:

- data contract is clear
- observation layer is sufficient
- no PIT leakage
- common factors / redundancy addressed
- result survives reasonable perturbation
- null alternatives documented
- test counts reconciled
- claim language matches causal evidence

## Strategy Boundary

Neither role is authorized to optimize trades from terrain findings during this program stage.

The purpose is to expand the quality and resolution of the market map.
