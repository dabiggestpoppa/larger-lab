## 5. Security re-attack — approval authentication versus PIT admissibility

The 24 P2e parity probes passed inside the canonical run, and the 83 P2d probes passed with them. The rule they pin is single-sourced in `authority.pit_availability_refusal`, called by `verify_mapping_provenance`, inherited by `verify_liquidation_admission_provenance`, and called (then translated) by `verification._assert_intraday_pit`:

| Attack | Mapping entry | Record entry |
|---|---|---|
| no availability, any cutoff | `PIT_AVAILABILITY_MISSING` | same |
| date-only, same day intraday (00/09/15/23h) | `INTRADAY_PIT_AMBIGUOUS` | same |
| date-only, later day | admitted | admitted |
| date-only, earlier day | `APPROVAL_NOT_YET_AVAILABLE` | same |
| instant basis, ±1 minute and equality | refused / admitted / admitted | same |
| offset representations of one instant | agree | agree |
| DST repeated hour (01:30-04:00 = 05:30Z) | ordered by real instant | same |
| naive cutoff | `EVALUATION_TIME_REQUIRED` | `PIT_CUTOFF_REQUIRED` (shape refused earlier) |
| no cutoff, no availability | no PIT claim made | `PIT_CUTOFF_REQUIRED` |
| bare-date cutoff | frozen date-granular contract | same |
| revoked / expired | `APPROVAL_REVOKED` / `AUTHORITY_EXPIRED` | mapped |
| substituted manifest | `TRUSTED_ROOT_MISMATCH` | mapped |
| loader called directly | date-granular, **not** a PIT verdict (pinned by `test_p2e_16`) | n/a |

Approval **authentication** (do these bytes belong to the reviewed root, is the row approved, is the artifact digest right) is distinct from PIT **admissibility** (was the approval operative at that instant). The repair makes the second answer identical at every verifier; it does not upgrade authentication, and it does not make a PIT-admissible record replay-eligible.
