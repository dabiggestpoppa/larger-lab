## 4. Semantic comparability laws (03 §18) — the eight conditions

Before two normalized fields may be compared:

```text
1  sensor family same
2  economic definition compatible
3  interval semantics compatible
4  units compatible after explicit conversion
5  venue scope known
6  identity resolved
7  no blocking quality flags
8  equivalence class permits comparison
```

I09's operative law is condition 8, and it is a *law*, not a preference:

* `EXACT_EQUIVALENT` — the two fields carry the same economic definition; they
  may enter a cross-provider canonical metric **as if exact**.
* `NORMALIZABLE_COMPARABLE` — comparable **after** an explicit, registered
  transformation; the transformation must be named by a `methodology_id` that
  exists in the registry.
* `CORROBORATION_ONLY` — storable at T1, **may not** enter a cross-provider
  canonical metric as if exact (03 §11 verbatim). 07 F16 adds the companion
  rule: provider-native analytics (CVD, slippage, liquidity scores, aggregate
  liquidation volume) stay provider-native evidence and must not be promoted to
  a Fabric-defined common metric.
* `NOT_COMPARABLE` — refused.

**Exact equivalence vs merely similar definitions — the distinction I09 must
not blur.** "Similar" is not a frozen category; it is the failure mode the
whole registry exists to prevent. Two fields are *exact* only if the provider's
own definition, unit, interval semantics and direction convention coincide with
the canonical field's. A provider that publishes an *interval* aggregate where
the canonical field is a *point snapshot* is **not** exact (condition 3), even
when both are labelled the same metric. A provider that publishes a *cumulative*
counter where the canonical field is *interval-local* is **not** exact
(condition 3). A provider field whose native unit differs from the canonical
unit is comparable only after an explicit conversion (condition 4) — never
"exact". And 03 §12's "last verified date" plus 03 §13's `AMBIGUOUS` class
exist because a *stale* or *unverified* definition is not evidence of
equivalence at all.

**Blocking assumptions and known limitations (03 §11).** Both are mandatory
fields of a mapping. A mapping that cannot state its blocking assumptions is
not admissible; it must fail closed.

**Semantic confidence (03 §13).** `AMBIGUOUS` **blocks use in critical T1
normalized fields**. Community evidence can support corroboration but can
never masquerade as first-party semantics. Note the measured state: all six
existing mappings carry `evidence_reference: BLOC2_PROBE_PENDING`, i.e. **no
mapping is currently evidence-backed**; every one of them is a planning
assertion. I09 must not upgrade a mapping's class or confidence without
replacing the pending evidence reference with real evidence.

**Comparability must live in the canonical library (03 §18, verbatim).** "This
gate belongs in the canonical library so research cannot bypass it casually."
`research/` code must not be able to compare two normalized fields without
passing the gate. This is the strongest argument for putting `comparability.py`
in the canonical library at all, and for its owner being I09 or I19 rather
than a research-side helper.

**No cross-venue synthesis (07 F24).** The comparability gate never creates a
cross-venue consensus. Two venues' fields may be *comparable*; that is not a
licence to pool them. T1 stays provider/venue/source explicit.

03 §12 requires each mapping to record an **evidence reference**; 03 §13
requires a semantic confidence and a last-verified date; 06 §5 requires the
fixture policy (raw fixture copied from verified source evidence or minimized
without semantic mutation; provenance documented; expected canonical output

The measured position: **zero** of the six existing mappings carries real

**I09 therefore has two separable halves, and the operator should decide

```text
I09-a  the registries themselves (models, readers, fail-closed lookup,
        versioning, comparability law) -- implementable now, offline,
```

`AMBIGUOUS`/pending) and a comparability gate that refuses everything it
cannot prove. That is the fail-closed shape the frozen contract wants, and it
is **not** the same as claiming provider semantics.

## 6. Missingness provenance

03 §14 requires the missing reason to remain explicit, and the operative frozen
vocabulary is **05 §12's thirteen members** (which "preserves Bloc 1/4 missing
reasons and adds normalization-specific reasons"). I09's contribution is
*provenance*, not a new vocabulary: when a mapping is absent, when a field is
`NOT_SUPPORTED` for a provider, or when a semantic decision blocks a value,
the record must say **which** reason applies and **why**, and it must stay
distinguishable from a verified zero.

Measured: the vocabulary and the typed-missingness laws are already in the
ratified I01 base (`normalization/enums.py:115-144`,
`normalization/models.py:594-628`), and `BLOCKED_STATUS_MISSINGNESS_REASON`
already binds each blocked status to its cause. Set-difference against 05 §12
is **0 missing / 0 extra**. **I09 must reuse thatvocabulary, not fork it.** A new `missingness.py` that re-declares the reasons
would create a second, divergent source of truth — 05 §12's own rule ("No
generic `missing=true` should erase the reason") and 03 §22 inv.8 ("semantics
can fail closed without discarding raw evidence") both point the same way, and
07 F15 requires semantic equivalence to be *operational*, not documentary. (Note:
03 §14's `SEMANTICS_UNVERIFIED` is a *quality flag* under 05 §11, not a
missingness reason — a second, divergent source of truth that an I09
implementer could easily create by transcribing 03 §14 literally instead of

## 10. Stop conditions (I09 must halt, not improvise, on any of these)

1. a mapping cannot state its **blocking assumptions** and **known
   limitations** — refuse the mapping (03 §11);
2. a required provider field's definition is **unverified** — it stays
   `AMBIGUOUS` and is barred from critical T1 fields (03 §13);
3. the only available evidence is **community-documented** — corroboration
   only, never first-party (03 §13);
4. a comparison would require a **cross-venue synthesis** — refuse (07 F24);
5. a comparison would require a **T2 research feature** — refuse (03 §20);
6. a formula would change **under an existing methodology id** — bump the
   version or refuse (07 F14);
7. a mapping is missing because a **provider has not been probed** — the
   absence is recorded as `NOT_REPORTED` / `NOT_SUPPORTED` / `HISTORY_UNAVAILABLE`
   per 03 §14; it is never filled by a similar-looking mapping;
8. the **identity is unresolved** or the **market availability is unknown** —
   comparability cannot be asserted (03 §18 conditions 6 and 7; 06 §12);
9. the only way to satisfy a frozen field is to **invent** a provider
   definition, a methodology or an equivalence class — stop and report;
10. the ratified I08 evidence would have to be **rewritten** to accommodate I09
    — stop; an amendment requires the same operator ruling I08 received.
