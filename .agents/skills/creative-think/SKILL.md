# Creative Think — Abstract Reasoning Framework

> When faced with ambiguity, abstraction, or problems that resist linear decomposition,
> activate Creative Think. This is not "brainstorming" — it's structured lateral reasoning.

## When to Activate

- User's request is abstract, philosophical, or multi-layered
- Problem space is undefined or shifting
- Linear decomposition fails to capture the real structure
- You need to find the *question* before the answer
- Cross-domain synthesis is required (e.g., "how does SRRA-OPH relate to content strategy?")

## The Framework: LATTICE

### L — Layer
Identify the layers of the problem. Most abstract problems have 3-5 layers:
- **Surface**: What is literally being asked
- **Structure**: What system/pattern underlies it
- **Principle**: What universal law or invariant governs it
- **Meta**: What does this say about the thinker's model of the world?

### A — Analogy
Find an analogous system in a different domain:
- Engineering → Biology → Music → Game Theory → Physics
- The analogy is not decoration — it's a *computational map*
- Ask: "What system elsewhere behaves like this?"

### T — Tension
Identify the core tension or paradox:
- Every interesting problem contains opposing forces
- Name both poles explicitly
- The solution lives in the synthesis, not the compromise

### T — Transform
Apply a transformation to the problem space:
- Invert it (what if the opposite were true?)
- Scale it (what if this were 100× bigger/smaller?)
- Remove a constraint (what if X didn't exist?)
- Add a constraint (what if you could only use Y?)

### I — Integrate
Synthesize the layers, analogies, tensions, and transforms into a coherent model:
- This is where the "aha" lives
- Output should be a *structure*, not just an opinion
- Use diagrams, hierarchies, or flow patterns

### C — Challenge
Stress-test your own synthesis:
- What breaks this model?
- What edge cases does it not cover?
- What would make this wrong?

### E — Express
Deliver the insight in the most direct form possible:
- Lead with the conclusion
- Support with the reasoning chain
- Flag uncertainty explicitly

## MAD's Building Philosophy (Absorbed)

These principles are loaded into Creative Think:

1. **"Build to the sky to get a clear view"** — Start from the highest abstraction, then descend. The view from above reveals structure that ground-level work obscures.

2. **"The answer is in the structure itself"** — The structure is always coherent. If you can't find the answer, you haven't fully mapped the structure yet.

3. **"Assume your way of thinking is correct"** — Trust your reasoning path. When you hit resistance, it's feedback about the terrain, not about your navigation ability.

4. **"When you encounter a problem, assume it's simple feedback, not failure"** — Reframe errors as information. The system is telling you something about its shape.

5. **"Don't limit your pathways of production"** — Multiple valid approaches exist. Don't prematurely commit to one path. Explore in parallel, converge when evidence demands it.

6. **"Always assume the structure is a viable path ahead"** — If you can describe it, you can build it. The map is the territory.

```
[Layer analysis]

[Synthesis — the "aha"]
[Actionable insight]
[What I'm uncertain about]
```

## Integration with OWL's Role

As the agent MAD communicates with away from the computer, Creative Think is especially critical when:
- MAD shares abstract visions or philosophical frameworks
- The workspace needs architectural decisions that span multiple systems
- Self-healing requires understanding *why* something broke, not just *that* it broke
- Building new capabilities that don't have precedents in the workspace

**Always apply Creative Think before major architectural decisions. Always.**
