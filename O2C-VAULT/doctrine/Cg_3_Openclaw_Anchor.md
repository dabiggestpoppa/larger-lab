# CG-3 OPENCLAW STRUCTURAL ANCHOR (MAD 2026-05-28)

> Critical directive: CG-3 augments OpenClaw. It does NOT replace it.

## Core Principle
OpenClaw already has: agent runtime, memory layer, tool layer, planning loop, workspace persistence, multi-session continuity, orchestration patterns, execution routing, autonomous workflows.

The issue is NOT lack of capability. The issue is lack of **structural operational cognition**.

## What CG-3 Actually Does
Upgrades planning flow, dependency awareness, operational relationships, propagation reasoning, topology stability checks — INSIDE OpenClaw's established runtime loop. NOT outside it.

## OpenClaw Features to Leverage (NOT Replace)

| Feature | How CG-3 Uses It |
|---------|-----------------|
| **AGENTS.md / SOUL.md / MEMORY.md** | Inject topology cognition habits, execution flow, governance sequencing |
| **Memory Layer** | Store topology lessons, failure chains, dependency failures, rollback patterns |
| **Tool Layer** | Enhance tool selection/sequencing through dependency awareness and topology validation |
| **Session + Workspace Model** | Understand operational state, track repo topology, maintain continuity awareness |
| **Planning Loop** | Upgrade the structure of planning cognition itself — this is the REAL target |

## Required Additions (All Lightweight)

1. **Topology Thinking Template** — Small internal planning structure: Objective → Nodes → Dependencies → Risks → Validation → Execution
2. **Dependency Check Habit** — Before execution: what depends on this? what breaks? what propagation? what rollback?
3. **Execution Topology Memory** — Store failure propagation patterns, dependency lessons, rollback lessons in existing MEMORY.md
4. **Tool Sequencing Governance** — Improve ordering, validation, dependency handling, execution gating (NOT rebuild tooling)
5. **Structural Validation Layer** — Before action: check dependency completeness, rollback presence, propagation exposure, continuity stability

## What Should NOT Happen
- NO OpenClaw runtime rewrites
- NO orchestration engine replacement
- NO giant topology systems
- NO recursive graph engines
- NO core framework mutation
- NO ontology bloat

## Correct Mental Model
```
OpenClaw Runtime → Memory + Tools + Planning
Planning → Topology Overlay → Governance + Validation → Improved Execution
```
This is AUGMENTATION. NOT replacement.

## Implementation Stack
```
AGENTS.md + SOUL.md + MEMORY.md → Planning Loop → Topology Overlay
→ Validation Layer → Tool Sequencing → Execution
```

## Success Condition
Phase succeeds when OpenClaw agents naturally: recognize dependency chains, understand propagation, validate topology stability, preserve continuity, sequence tools intelligently, detect structural incompleteness — WITHOUT giant prompts, framework rewrites, infrastructure mutation, or constant operator correction.
