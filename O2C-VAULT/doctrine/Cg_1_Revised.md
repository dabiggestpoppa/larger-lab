# CG-1 REVISED IMPLEMENTATION MODEL (MAD 2026-05-28)

> Approved architecture. Phase CG-1 = lightweight orchestration overlay, NOT infrastructure surgery.

## Core Principle
**OC2 carries doctrine. OCE handles substrate. These are separate layers with different densities.**

## Layer Separation

| Layer | Role | Character |
|-------|------|-----------|
| **OC2** | Fast operational overlay — doctrine, planning, validation, orchestration | Lightweight, adaptive |
| **OCE** | Deep field — continuity, persistent substrate, large-scale cognition | Heavy, persistent |
| **Execution** | Tools, agents, runtime | On-demand |

## Architecture
```
Operator → OC2 (overlay) → OCE (field) → Execution
```
- OC2: active interaction, lightweight cognition, operational governance
- OCE: deep continuity, field operations, persistent substrate logic
- Separation prevents cognitive mud — not everything becomes the field

## CG-1 Deliverables (Revised)

### Done
1. **Master Doctrine Prompt** — SOUL.md updated with classification gate at #1, topological cognition directive, execution gating habit

### Pending (awaiting MAD direction)
2. **Domain-Specific Micro-Doctrines** — Tiny lightweight overlays per domain (trading, coding, deployment). Activated dynamically, NOT giant context dumps
3. **Pre-Execution Validation Habit** — Internal checklist before any tool call:
   - What constraints exist?
   - What could fail?
   - What validation is missing?
   - What structure is incomplete?
4. **Micro-Topology Generation** — Tiny internal structure maps (not Mermaid dumps). Goal → Risk → Validate → Execute
5. **Execution Gating** — Execution is EARNED. Validate → Constrain → Simulate → THEN execute

## Critical Rules
- NO OCE rewrites for CG-1
- NO SRRA modifications for CG-1
- NO OpenClaw core modification
- All changes are to OC2 cognition flow, prompting architecture, planning templates
- Cheaper, faster, lower entropy, less brittle, easier iteration/rollback
- Works WITH OpenClaw, not against it

## Implementation Model
```
User Task → OC2 Core → Doctrine Overlay → Topology Thinking → Validation → Plan → Execute
```

## Anti-Pattern (DO NOT)
- Everything becoming the field
- Heavy infrastructure for lightweight cognition problems
- Giant context dumps instead of activated micro-doctrines
- slowness, dependency, complexity from over-integration
