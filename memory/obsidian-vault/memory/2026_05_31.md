## Active Investigation: Python ST vs Nautilus Trade Count Discrepancy

**Status: IN PROGRESS — Awaiting Architect Review**

### Problem
- XAUUSD: Python ST finds 604 trades, Nautilus finds 1,718 trades (2.84x difference)
- Manual indicates 1k+ trades expected (matches Nautilus, not Python)
- MAD confirmed: "it's not a bug, Python was just under-delivering"

### What Was Tested
1. Tier config comparison — **IDENTICAL** (T1/T2/AU/trigger all match)
2. NO-GO rate — 76.8% of sessions filtered (AR > 95p for gold), leaving 316 active
3. Trade funnel — VERY tight: 243 impulses -> 230 retraces -> 222 entries (97% conversion)
4. Session init timing — **IDENTICAL** (both set swing_origin from first post-init bar)
5. Asian bar filtering — Nautilus explicitly skips Asian hours; Python processes them (would give Python MORE trades, not fewer)
6. Kill switch logic — **IDENTICAL** (80% retracement threshold)
7. Loop counting — **IDENTICAL** (5 loops max)
8. SL/TP logic — **IDENTICAL** (zero-buffer extreme, close-only SL; 1 AU TP)

### Likely Root Cause (Unconfirmed)
**Bar data or timestamp handling difference** between:
- Nautilus: `BarDataWrangler` -> Nautilus Bar objects -> `on_bar()` callback
- Python: `load_m5_csv()` -> custom Bar objects -> `run()` method

Nautilus might produce more bars per session, process bars in different order, or have different EST hour classification leading to more sessions qualifying.
