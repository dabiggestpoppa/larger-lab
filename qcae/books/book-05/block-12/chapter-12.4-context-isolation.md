# Chapter 12.4 — Context Isolation

## Mission

Prevent accumulated conversation, prior candidate enthusiasm, irrelevant project history, or another worker's assumptions from contaminating specialized analysis.

## Context Layers

Workers may receive:

```text
constitutional invariants
relevant contract/atom slice
task-specific artifact refs
policy/tool permissions
explicit prior findings required for the task
```

They should not automatically receive all previous prose.

## Context Packet

Each invocation should assemble a reproducible Context Packet containing references and summaries with provenance. The packet itself is versioned/hashable where practical.

## Hypothesis Separation

Claims from earlier workers are labeled by verification state. A security worker should not treat a discovery worker's belief as fact; a proving worker should receive the source-grounded forensic package rather than persuasive repository marketing.

## Quant Independence

For sensitive research validation, separate source reconstruction from independent evaluation where practical. The validator receives the reconstructed specification and experiment identity, not an instruction to "confirm the reported edge."

## Memory Retrieval

Long-term memory is queried purposefully. Retrieval should include negative evidence and contradictions, not only semantically similar positive notes.

## Context Compression

Summaries may reduce token cost but cannot delete material uncertainty, hard failures, evidence scope, or authority status.

## Invariants

1. Context is assembled per task.
2. Earlier claims retain verification labels.
3. Negative/contradictory evidence is retrievable.
4. Summarization cannot erase hard state.
5. Independent validation is protected from unnecessary persuasive context.
6. Full-chat continuity is never required for correctness.

## Exit Criteria

Workers can be restarted in fresh model sessions using durable Context Packets and still reach auditable results.
