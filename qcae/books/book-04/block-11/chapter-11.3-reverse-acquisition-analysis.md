# Chapter 11.3 — Reverse Acquisition Analysis

## Mission

Ask the inverse of normal QCAE discovery:

> If we were designing Quant Lab today, would we choose to own this internal capability in its current form?

## Process

```text
internal implementation
→ recover actual capability atoms/consumers
→ establish ownership burden
→ retrieve known external/internal alternatives
→ run targeted delta discovery if needed
→ compare net capability gain
→ propose keep/consolidate/replace/extract/deprecate
```

## Current System as Candidate

Internal code receives no automatic preference merely because it already exists. But migration/switching risk and embedded knowledge count as real value/cost.

## External Replacement

Any external challenger still passes Books II/III. Reverse acquisition is not a shortcut around proof.

## Internal Extraction

A valuable atom trapped inside a large internal framework may itself be extracted behind a smaller boundary.

## Invariants

1. Existing internal code is evaluated as an acquisition choice.
2. Sunk cost does not equal future value.
3. Migration/embedded knowledge count honestly.
4. External alternatives still require full evidence gates.
5. Reverse acquisition can recommend internal extraction, not only external replacement.

## Exit Criteria

QCAE can explain whether continued ownership of an internal capability is rational relative to current alternatives.
