# Chapter 9.4 — Negative Knowledge Memory

## Mission

Preserve failed searches, rejected candidates, broken assumptions, incompatibilities, invalid alpha, security findings, and dead-end integration paths as first-class engineering intelligence.

## Negative Memory Types

```text
NOT_FOUND
NOT_CAPABLE
CONTRACT_FAILURE
BUILD_FAILURE
SECURITY_REJECTION
LICENSE_REJECTION
QUANT_INVALIDATION
PERFORMANCE_FAILURE
EXCESSIVE_BURDEN
DUPLICATE_CAPABILITY
ABANDONED_PATH
```

## Why It Matters

Without negative memory, autonomous agents repeatedly spend budget proving the same bad idea. A rejection can be more valuable than another candidate list.

## Reconsideration

Negative knowledge must include the conditions under which it could become obsolete: new revision, changed license, new contract, different acquisition form, new data, fixed vulnerability, or different environment.

## Failure Detail

Store causal evidence, not only `FAILED`. Example: "v2.4 fails ordering clause C-17 on duplicate events" is reusable; "repo bad" is not.

## Invariants

1. Failure is durable knowledge.
2. Rejection reasons are causal and scoped.
3. Negative memory can expire/be superseded under explicit changed conditions.
4. Failed alpha can coexist with useful software capability.
5. Agents consult negative memory before expensive rediscovery.

## Exit Criteria

QCAE can recognize previously explored dead ends and know exactly what must change before reconsidering them.
