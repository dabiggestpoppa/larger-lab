# Chapter 9.3 — Positive Knowledge Memory

## Mission

Preserve reusable findings about capabilities, sources, specifications, implementations, tests, and successful integration patterns without turning prior success into permanent truth.

## Positive Memory Examples

- library implements atom X;
- specific revision passed contract Y;
- adapter pattern worked for framework Z;
- specification clarified edge case A;
- benchmark environment established baseline B;
- internal module already satisfies capability C.

## Retrieval Keys

Index by capability/atom, repository/package, specification, dependency, interface, domain, failure/edge-case tags, and evidence state.

## Evidence Link

Every material memory item links to evidence/receipt. Unsupported agent summaries are notes, not promoted knowledge.

## Reuse

Prior successful tests may seed future proof plans, but current relevance is checked against revision/contract/environment before reuse.

## Invariants

1. Positive memory is evidence-linked.
2. Past success remains scoped.
3. Retrieval is capability-centric, not only repository-centric.
4. Reuse does not bypass freshness checks.

## Exit Criteria

Future acquisition work can start from accumulated verified knowledge instead of rediscovering the same facts.
