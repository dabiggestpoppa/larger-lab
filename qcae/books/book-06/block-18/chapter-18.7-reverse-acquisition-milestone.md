# Chapter 18.7 — Reverse-Acquisition Milestone

## Mission

Define when QCAE is mature enough to proactively inspect Quant Lab itself and recommend build-vs-borrow, consolidation, replacement, extraction, or retirement opportunities without becoming an uncontrolled refactoring agent.

## Entry Preconditions

- capability registry has meaningful internal coverage;
- receipts/negative knowledge are trustworthy;
- internal repository search works;
- monitoring/revalidation works;
- acquisition benchmarks pass;
- human/policy escalation paths are stable.

## Milestone Work

```text
internal capability census
→ atom mapping
→ duplicate implementation detection
→ maintenance/burden signals
→ external alternative discovery
→ comparative proving where justified
→ engineering opportunity ranking
→ proposal packets
```

## Proposal Outcomes

```text
KEEP
CONSOLIDATE
STANDARDIZE_INTERFACE
EXTRACT
REPLACE
DEPRECATE
INVESTIGATE
```

These remain proposals. QCAE cannot autonomously delete branches, rewrite architecture, replace production systems, or retire capability merely because its analysis prefers another path.

## Qualification

Use synthetic/internal benchmark fixtures containing:

- duplicate utilities with one canonical winner;
- intentional redundancy that should remain separate;
- old code that is cheaper to keep than replace;
- framework bloat where extraction is superior;
- external alternative that appears cheaper but fails proof;
- orphan capability that should be retired.

## Engineering Capital Metric

Ranking should consider expected maintenance savings, risk reduction, capability gain, migration burden, evidence quality, and reversibility—not raw LOC reduction.

## Invariants

1. Reverse acquisition begins only after memory/proving are mature.
2. Proactive intelligence never becomes unilateral refactoring authority.
3. Intentional redundancy is distinguishable from waste.
4. External alternatives receive normal proving.
5. Engineering-capital savings include migration/ownership risk.
6. Every proposal is evidence-backed and reversible where possible.

## Exit Criteria

QCAE can proactively surface high-value engineering opportunities while leaving the final architectural action under explicit authority.
