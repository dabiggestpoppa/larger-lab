## Book VI Core Transformation

Book VI converts QCAE from a frozen architecture into an executable engineering campaign. It defines how the system itself is tested, how operators interact with it, and how the coding agent advances through phases without inventing architecture or declaring success from code volume.

## Book VI Frozen Laws

1. QCAE must prove itself against known-answer and adversarial fixtures.
2. Core, providers, workers, discovery, comprehension, security, sandbox, evidence, acquisition, and quant layers each have dedicated qualification.
3. Happy-path success is insufficient for release.
4. Operators interact through capability contracts, jobs, receipts, evidence, and scoped approval—not implicit chat state.
5. Urgency can change priority but not evidence or authority requirements.
6. Monitoring detects and proposes; it does not auto-upgrade.
7. Breakage and security events use known-good state, graph-derived blast radius, rollback, and re-proof.
8. Retirement preserves institutional memory.
9. The coding agent follows P0–P12 in order unless an explicit roadmap amendment is committed.
10. Every phase produces a machine-readable evidence manifest.
11. Standalone QCAE is useful and releasable before OCE is available.
12. DeepWiki integration follows local comprehension correctness.
13. Quant validation follows generic proving and must enforce the CEREBUS/manual-first firewall.
14. Agent autonomy follows service correctness; it is not a substitute for it.
15. Reverse acquisition follows mature evidence/registry/monitoring infrastructure.
16. OCE governance migration is the final phase and uses provider substitution rather than core rewrite.
17. Phase and release freezes are evidence states, not optimistic labels.
18. Canon changes after freeze require explicit amendment and scoped requalification.
